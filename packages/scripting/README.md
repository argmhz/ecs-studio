# @ecs/scripting

`defineScriptDefinition` declares stable script metadata and inspector properties using `@ecs/scene` field schemas. `validateScriptProperties` applies defaults and returns path-based diagnostics. Code scripts and visual graphs receive the same `createScriptApi` contract:

- `create` runs once when attached; `start` begins each Play session; `update` runs per rendered frame; `fixedUpdate` runs per fixed simulation step; `event` runs for delivered subscribed events; `destroy` runs on stop, removal or reload.
- `properties` and delivered `events` are read-only JSON snapshots. `state` is per-script persistent JSON state supplied back by the host on the next invocation.
- `input` is the read-only action and pointer snapshot for this update. Actions expose `value`, `pressed`, `justPressed` and `justReleased`; pointer coordinates are normalized to canvas space `[-1, 1]`.
- Component reads are copies. `getComponent`, `setComponent`, `addComponent` and `removeComponent` address the owning entity. Their `*EntityComponent(entityId, typeId, ...)` counterparts target an explicit stable scene ID from the invocation's component snapshot. They create commands; scripts never receive a `World`, DOM or GPU object. The host validates target IDs, component schemas and data, then applies the whole tick's command buffer only after all script invocations finish. Registered components can be added and removed during Play; integrations reconcile renderer/physics resources from the updated ECS snapshot before the next fixed physics step.
- Editor scene objects always have `engine.name` and `engine.transform2d`. Scripts may update either component, but the host rejects attempts to remove either required component; older imported scenes receive the default name `Object` when opened.
- `subscribe`, `unsubscribe` and `emit` use stable event names and JSON payloads. Code scripts additionally expose `on(type, callback)` and `off(type, callback)`; callbacks register in `onStart` and receive the event plus a fresh API snapshot. `onUpdate` runs per simulation tick, `onStop` runs before Play teardown, and legacy `update` remains valid. `finish()` closes the invocation and returns state, commands, emitted events and subscriptions. A destroy invocation clears subscriptions.

Each invocation has limits for JSON values (256 KiB each), 256 component commands, 256 delivered/emitted events and 256 subscriptions. The editor Play host runs scene-bound scripts in stable entity-ID order, with code before the graph for each binding. All bindings receive the same component and input snapshots for the tick; commands apply in invocation order after all bindings finish, so later commands win on conflicting fields. `api.input.actions` exposes `moveX`, `moveY`, `jump` and `interact`, with analog `value` plus `pressed`, `justPressed` and `justReleased`. `api.input.pointer` uses normalized canvas coordinates from `-1` to `1` and includes `inside`, `primary` and `secondary`; `connectedGamepads` lists connected device indices. The node editor's Input Action node returns the chosen action state as JSON. Emitted events are buffered until the next update and delivered only to bindings that subscribed during their previous invocation. Every code/graph binding has independent state and subscriptions; the shared pending event queue is capped at 512 events per update. Other hosts must document their own scheduling contract.

The browser Play host also forwards Rapier overlap events to the next script update as `physics.collision.enter`, `physics.collision.exit`, `physics.trigger.enter` or `physics.trigger.exit`. Their JSON payload is `{ entityId, otherEntityId }`. Physics events share the host's 512-event pending queue cap with script-emitted events.

Prototype for bounded project-script execution. `runSandboxed(source, options)` runs a one-shot JavaScript function-body in an opaque-origin iframe and nested Blob Worker with host-owned timeout/cancellation. `createSandboxedSession(source, options)` keeps the same isolated worker alive for a Play session while enforcing a host-owned timeout on every invocation; cancellation/close removes the iframe and worker. It only transfers JSON; source, input and result default to 256 KiB each. The sandbox blocks DOM, IndexedDB and `connect-src` network requests in the Chromium check.

This is defense in depth, not a guarantee against browser vulnerabilities or memory exhaustion. `runSandboxed` accepts JavaScript source; the editor transpiles TypeScript in Monaco's local language worker before passing code to it. Project module imports/exports and plugins are not executed. `runIsolated` remains a trusted-local-snippet experiment and must not be used for project code.

`runNodeGraph` is a small declarative control-flow budget helper. `visual-graph.ts` adds the versioned graph format, typed execution/data ports, connection validation and a bounded interpreter for `On Start`, `On Update`, `On Event`, JSON/number values, variables, comparison, branching, repeat loops, component read/write and event payload/emit/subscribe nodes. The Play host runs On Start once per graph instance, On Update each simulation tick, and matching On Event flows only for subscribed event deliveries. Existing `event.start` graphs remain supported as legacy per-tick entrypoints. `evaluateVisualGraph` runs against the same `ScriptApi` as code scripts and returns its schema-hosted component commands, state, events and subscriptions. Repeat is limited to 1,000 iterations and each run is limited to 10,000 node visits; callers may also cancel with an `AbortSignal`.

`createCodeScriptSource` builds the worker-side API wrapper for TypeScript or JavaScript lifecycle functions. The editor compiles TypeScript locally at Play, invokes the wrapper in a per-binding sandbox session, validates returned component commands against scene schemas, and applies them to the copied Play scene. Event callbacks live in that session and events emitted during one tick are delivered no earlier than a later tick.

Run its unit tests with `npm run test:scripting`; browser isolation checks are in `tests/editor.spec.ts`.

The audio host also consumes `audio.play` and `audio.stop` events with `{ entityId: string }` payloads. They target an entity's `AudioSource2D` component and follow the regular next-tick event delivery; scripts never receive browser audio objects.

The Game-view UI host emits `ui.button.clicked` with `{ entityId: string }` when an enabled `UiButton` is pressed. Code scripts may register an `api.on('ui.button.clicked', callback)` listener in `onStart`; visual graphs connect `On Start` to `Subscribe Event`, then handle the matching event through `On Event` and read its payload with Event Payload. Both forms can update schema-backed UI components through the shared command API.
